已经做成的工作台

下图是运行中的首版，内容与版本记录来自隔离的合成演示库。

左侧按课程与课次导航；中间选择参考、阅读和编辑；右侧展示笔记阶段、作业提交状态、资料采集与真实 Git 父节点关系。

01 / 资料在哪里

两个目录，清楚可见

笔记库与下载库可分别设置。资料卡显示来源与文件位置，文本和 PDF 可预览；跨课次参考只在本课程内显式复制，保留原件、拒绝覆盖同名文件。

02 / 本课有哪些参考

明确选择，保留缺口

只采用勾选的文件与 PDF 页码范围。缺少教师课件、智云 PPT 或手写笔记时，可以记录待检查、本课未提供或存在待补充。

03 / 从参考到正文

生成草稿，再编辑保存

支持可配置的兼容 API、Pi 和 Codex 单次整理。正文在界面内编辑；切换课次或设置前保留草稿，草稿重写和正式文件覆盖都有私有备份。

04 / LaTeX 与 PDF

沿用已有笔记版式

已有导言区优先，新课次可读取本机模板。安装 XeLaTeX 后可双遍编译；失败保留原 PDF，中间文件留在私有临时目录。生成 PDF 后由你确认版式。

05 / 采集课程资料

连接现有 Scholar 能力

通过外部增强版 zju-scholar 请求课件、智云 PPT、字幕和录像；课程与录像 ID 显式填写。空集合、拒绝下载、部分成功分别报告，不把请求结束当作全部下载成功。

06 / 提交与进度

作业状态与 Git 版本并列

个人提交状态缺失时保留未知，不完整刷新保留旧缓存。Git 图使用真实 commit 与父节点；按钮只提交当前笔记源稿，暂存区有其他改动时拒绝混入，不自动 push 笔记库。

平台提交、笔记完成与 Git commit 是三个独立事实。

右侧把它们放在一起看，但不会互相推断。完成阶段由你确认；本地保存成功也不代表已经向学在浙大提交作业。

保持轻量，保留迁移空间

TypeScript 浏览器界面→本机 Python 服务→文件库 / 外部 Scholar / 模型 / Git

前端仅 TypeScript 与 CSS，Vite 负责构建；生产界面无需第三方运行库。后端使用标准库，直接依赖为 pypdf 与 keyring。没有数据库服务、云端账号系统或供应商 SDK。

路径均来自配置；原项目保留原位。源码不复制 ZLA 或 Scholar，只通过窄的外部进程边界连接 Scholar。本仓库采用 MIT，外部项目许可证保持独立。

本机状态、API 密钥、原始课程材料与草稿不进入公有仓库。现有笔记项目的用户改动保留；本轮验证没有访问真实学校账号，没有产生真实模型调用，也没有提交或推送你的正式笔记。

在你的电脑上使用

项目位于 Workspace 的 projects/zju-study-workbench。当前本机私有首用配置已连接既有 course-notes-lab 与 Scholar，下载暂存选用笔记项目的 ZLA 目录；没有发起下载或改动正式课程文件。

# 在项目目录，首次安装 / 换电脑：
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
npm ci
npm run build

# Windows：打开实际工作台
./start.ps1

# 只看合成演示，无学校连接与模型调用
./start.ps1 -Demo

# macOS / Linux 或不用启动脚本
python -m server --open

首用在设置里核对资料目录、课程与录像 ID、模型地址。外部 Scholar 需具备 courseware-download 的 --materials-root、智云 courseware-pdf、字幕 API 与 download_video(root=...) 等增强能力；普通上游版本不保证满足此合同。密钥存入系统密钥环，本机状态默认在 ~/.zju-study-workbench。
